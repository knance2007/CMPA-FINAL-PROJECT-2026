# Project Plan: Fictional Criminal Defense Law Firm Website

## Project Overview

This project involves creating a functional multi-page website for a fictional law firm specializing in criminal defense. The website will be built using HTML and CSS, hosted on a professional GitHub repository with a clear file structure and a well-thought-out README. Additionally, three planned documents will be created: scope, plan (this document), and retrospective.

**Objectives:**
- Develop a professional, functional website.
- Maintain a clean GitHub repository.
- Ensure organized file structure.
- Produce comprehensive documentation.

**Timeline:**
- Preferred deadline: Thursday evening.
- Actual deadline: Friday May 8th, 2026.

## Risk Analysis (TAME Framework)

The TAME framework is used to assess risks by identifying Threats, Assets, Mitigations, and Exposures.

### Threats
- Errors in HTML/CSS code leading to broken functionality or poor user experience.
- GitHub repository issues, such as access problems or merge conflicts.
- Time management issues causing delays in meeting deadlines.
- Inability for professor and peers to view the website due to compatibility or hosting issues.

### Assets
- The website itself (HTML/CSS files) as the core deliverable.
- GitHub repository containing the project code and documentation.
- Project documents (scope, plan, retrospective) for planning and evaluation.
- Personal time and effort invested in the project.

### Mitigations
- Regularly test HTML/CSS code in multiple browsers to catch errors early.
- Use Git best practices (frequent commits, branches for features) to manage repository issues.
- Create a detailed schedule and stick to it; use time-blocking techniques for better management.
- Ensure the website is hosted on GitHub Pages or a similar accessible platform; test viewing on different devices.

### Exposures
- Potential for project delays if time management fails, risking missing the preferred Thursday deadline.
- Risk of lower grades if the website has errors or is inaccessible.
- Loss of productivity if GitHub issues arise without backups.
- Exposure to technical debt if code is not reviewed and refactored.
